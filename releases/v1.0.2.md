# v1.0.2

[English](v1.0.2.md) | [Русский](v1.0.2.ru.md)

Documentation, licensing, and repository-maintenance release for the ELAN `04f3:0c4b` fingerprint integration.

This release does **not** introduce a new ELAN driver build or a new Debian package version. The tested packaged binary remains:

`elan-fingerprint-04f3-0c4b-local_1.0.0+local1_amd64.deb`

SHA256:

```text
9893258dfeb04259312fccb465ac372440e2e972787966794e63b87c9c520b44
```

## What changed since v1.0.1

### OpenSSL 1.1 provenance and licensing

The provenance and redistribution terms for the private `libcrypto.so.1.1` compatibility library are now documented explicitly.

- source binary package: `libssl1.1_1.1.1f-1ubuntu2.24_amd64.deb`
- corresponding Ubuntu source package: `openssl 1.1.1f-1ubuntu2.24`
- verified package, library, and source-file SHA256 values are recorded in the repository
- OpenSSL 1.1.1f is documented as being distributed under both the **OpenSSL License and Original SSLeay License**
- the complete upstream OpenSSL 1.1.1f license text and a provenance record are included in the package tree
- OpenSSL remains third-party software and is not relicensed under the repository's Apache-2.0 license

See [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) and [`docs/en/PACKAGE.md`](../docs/en/PACKAGE.md).

### Documentation synchronization

- synchronized the English and Russian licensing documentation
- updated `README.md` so the `libcrypto.so.1.1` licensing status is stated explicitly
- improved Russian terminology and removed unnecessary English wording while preserving technical literals
- refined Russian troubleshooting, uninstall, security, and contribution documentation

### Repository maintenance and contribution policy

The repository now includes additional project-maintenance material:

- issue templates for bug reports, compatibility reports, and feature requests
- pull request template
- English and Russian contribution guidelines
- English and Russian security policy
- English and Russian Code of Conduct

These additions document contribution expectations, security reporting, translation rules, and the handling of third-party binaries.

## Package status

There are **no binary, driver, runtime, PAM, udev, or Debian package version changes** in `v1.0.2`.

The Debian package remains `1.0.0+local1`, and its existing SHA256 remains valid for the published artifact listed above. The package tree now contains additional OpenSSL notice files, so any future rebuild from the current tree will produce a different `.deb` checksum and must be recorded as a separate binary artifact.

## Third-party components

The OpenSSL 1.1 compatibility component now has documented provenance, source-package mapping, checksums, and license notices.

The proprietary ELAN TOD binary is unchanged. Its redistribution status remains unresolved and continues to be tracked in Issue #1. This release must not be interpreted as resolving or granting redistribution rights for that component.
