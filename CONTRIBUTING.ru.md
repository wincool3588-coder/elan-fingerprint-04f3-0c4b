# Участие в проекте

[English](CONTRIBUTING.md)

Спасибо за помощь в улучшении поддержки сканера отпечатков ELAN `04f3:0c4b`.

## Перед созданием Issue

- Сначала проверьте существующие Issues.
- Используйте подходящую форму: bug report, compatibility report или feature request.
- Не публикуйте сведения об уязвимостях в публичном Issue; следуйте [SECURITY.ru.md](SECURITY.ru.md).
- Для вопросов лицензирования и распространения проприетарных компонентов ELAN или `libcrypto.so.1.1` используйте метку `legal/licensing` и сверяйтесь с [THIRD_PARTY_NOTICES.ru.md](THIRD_PARTY_NOTICES.ru.md).

## Сообщения об ошибках

Приложите достаточно данных для воспроизведения и диагностики:

- модель ноутбука или устройства
- версию Ubuntu
- версию ядра (`uname -r`)
- USB ID сканера (`lsusb`)
- версии `fprintd`, `libfprint-2-2`, `libfprint-2-tod1` и `libpam-fprintd`
- установленную версию `elan-fingerprint-04f3-0c4b-local`
- точные шаги воспроизведения
- ожидаемое и фактическое поведение
- релевантный вывод команд или фрагменты журнала без персональных данных

Полезные проверки описаны в [docs/ru/TROUBLESHOOTING.md](docs/ru/TROUBLESHOOTING.md).

## Отчёты о совместимости

Приветствуются результаты тестирования на других ноутбуках, версиях прошивки, ядрах и выпусках Ubuntu. Используйте форму compatibility report и явно укажите, что именно было проверено:

- enrollment
- `fprintd-verify`
- `sudo`
- экран блокировки GNOME
- графический вход
- резервная аутентификация паролем

Отрицательный результат совместимости тоже полезен, если приложена достаточная диагностика.

## Pull Requests

1. Создавайте отдельную рабочую ветку от актуальной `main`.
2. Ограничивайте каждый PR одним логическим изменением.
3. При изменении поведения или политики сначала обновляйте каноническую английскую документацию, затем русскую версию, если она существует.
4. При переводе сохраняйте команды, пути, имена пакетов, хеши, USB ID, сообщения об ошибках и другие технические литералы.
5. Опишите, как изменение было проверено.
6. При наличии связанного Issue укажите его в PR.

Изменения в `main` вносятся через Pull Request; для merge используется squash, чтобы сохранять линейную историю.

## Сторонние бинарные компоненты

Не добавляйте, не заменяйте, не перепаковывайте и не распространяйте через PR проприетарные бинарные компоненты ELAN, библиотеки совместимости OpenSSL, firmware или другие сторонние бинарные файлы, пока их происхождение, лицензия, условия распространения и контрольные суммы явно не документированы и не проверены.

Лицензия Apache-2.0 для материалов, созданных в репозитории, не перелицензирует сторонние компоненты. См. [THIRD_PARTY_NOTICES.ru.md](THIRD_PARTY_NOTICES.ru.md).

## Стиль

- Делайте документацию краткой и воспроизводимой.
- Предпочитайте команды, которые можно копировать без изменений.
- Не предлагайте разрушительные глобальные обходные решения, если можно использовать локальное для пакета решение.
- Не рекомендуйте для этого пакета глобальный `LD_LIBRARY_PATH`, изменения глобального `ld.so.conf` или небезопасные символические ссылки для `libcrypto`.
