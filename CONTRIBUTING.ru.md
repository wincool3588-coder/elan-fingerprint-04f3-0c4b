# Участие в проекте

[English](CONTRIBUTING.md)

Спасибо за помощь в улучшении поддержки сканера отпечатков ELAN `04f3:0c4b`.

## Перед созданием задачи

- Сначала проверьте существующие задачи.
- Используйте подходящую форму: сообщение об ошибке, отчёт о совместимости или запрос новой возможности.
- Не публикуйте сведения об уязвимостях в общедоступной задаче; следуйте [SECURITY.ru.md](SECURITY.ru.md).
- Для вопросов лицензирования и распространения проприетарных компонентов ELAN или `libcrypto.so.1.1` используйте метку `legal/licensing` и сверяйтесь с [THIRD_PARTY_NOTICES.ru.md](THIRD_PARTY_NOTICES.ru.md).

## Сообщения об ошибках

Приложите достаточно данных для воспроизведения и диагностики:

- модель ноутбука или устройства;
- версию Ubuntu;
- версию ядра (`uname -r`);
- USB ID сканера (`lsusb`);
- версии `fprintd`, `libfprint-2-2`, `libfprint-2-tod1` и `libpam-fprintd`;
- установленную версию `elan-fingerprint-04f3-0c4b`;
- точные шаги воспроизведения;
- ожидаемое и фактическое поведение;
- относящийся к проблеме вывод команд или фрагменты журнала без персональных данных.

Полезные проверки описаны в [docs/ru/TROUBLESHOOTING.md](docs/ru/TROUBLESHOOTING.md).

## Отчёты о совместимости

Приветствуются результаты тестирования на других ноутбуках, версиях прошивки, ядрах и выпусках Ubuntu. Используйте форму отчёта о совместимости и явно укажите, что именно было проверено:

- регистрация отпечатка;
- `fprintd-verify`;
- `sudo`;
- экран блокировки GNOME;
- графический вход;
- резервная аутентификация паролем.

Отрицательный результат совместимости тоже полезен, если приложена достаточная диагностика.

## Запросы на включение изменений (Pull Requests)

1. Создавайте отдельную рабочую ветку от актуальной `main`.
2. Ограничивайте каждый PR одним логическим изменением.
3. При изменении поведения или политики сначала обновляйте каноническую английскую документацию, затем русскую версию, если она существует.
4. При переводе сохраняйте команды, пути, имена пакетов, хеши, USB ID, сообщения об ошибках и другие технические литералы.
5. Опишите, как изменение было проверено.
6. При наличии связанной задачи укажите её в PR.

Изменения в `main` вносятся через Pull Request; при слиянии используется squash, чтобы сохранять линейную историю.

Не добавляйте, не заменяйте, не перепаковывайте и не распространяйте через PR проприетарные бинарные компоненты ELAN, библиотеки совместимости OpenSSL, прошивки или другие сторонние бинарные файлы, пока их происхождение, лицензия, условия распространения и контрольные суммы явно не документированы и не проверены.

Лицензия Apache 2.0 для материалов, созданных в репозитории, не перелицензирует сторонние компоненты. Для `libcrypto.so.1.1` применяются OpenSSL License и Original SSLeay License; подробности, происхождение и контрольные суммы приведены в [THIRD_PARTY_NOTICES.ru.md](THIRD_PARTY_NOTICES.ru.md).

## Стиль

- Делайте документацию краткой и воспроизводимой.
- Предпочитайте команды, которые можно копировать без изменений.
- Не предлагайте разрушительные общесистемные обходные решения, если можно использовать решение, локальное для пакета.
- Не рекомендуйте для этого пакета глобальный `LD_LIBRARY_PATH`, изменения общесистемного `ld.so.conf` или небезопасные символические ссылки для `libcrypto`.
